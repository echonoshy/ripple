Product

A real workspace for agent tasks.

Ripple is not another prompt box. It gives each user a persistent place where agents can resume sessions, read and write files, request connector authorization, generate outputs, and expose progress without moving server logic into the client.

From conversation to durable output

Users can move from a session into generated artifacts, inspect files, preview PDFs, upload inputs, and return later without losing the workspace.

Workspace

Capabilities and automations live beside the work.

Capabilities

Shared skills, custom skills, service integrations, and authorization state appear in one surface.

Connectors

Google Workspace, Feishu / Lark, Bilibili, and Notion access stays explicit and user-scoped.

Automations

Scheduled work uses the same sessions, permissions, sandbox, and execution boundary.

Settings

Account, quota, token usage, default model, language, and diagnostics stay close to the product surface.

Mobile

The same workspace, shaped for touch.

The Tauri mobile shell keeps the backend on Ripple Server and brings the product flow to iOS and Android: sign in, continue sessions, browse files, manage capabilities, and check automations from a bottom-tab mobile experience.

Platform

Product surface in front, Rust control plane behind it.

Ripple keeps backend responsibilities on the server: user isolation, session state, connector auth, approvals, schedules, skill manifests, and the OpenAI-compatible `/v1` API. Codex app-server remains the execution plane.

01

Control plane

Rust server manages users, workspaces, sessions, runs, quotas, and API boundaries.

02

Execution plane

Server-side Codex app-server performs the actual agent work under managed permissions.

03

Client surface

Web, Tauri desktop, iOS, and Android clients call Ripple Server instead of owning backend logic.
