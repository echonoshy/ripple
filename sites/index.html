Codex Control Plane

Ripple 涟漪

运行在 Codex app-server 之上的多用户 Agent 控制面。

Ripple 用 Rust 管理 user sandbox、session、run、workspace、connector 授权、 skill manifest、approval bridge、schedule 和统一 `/v1` API。真正的执行交给服务端 Codex app-server，客户端只负责展示和交互。

What Ripple Owns

Ripple 负责控制边界，Codex 负责执行任务。

01

Multi-user control

API key middleware 和 `X-Ripple-User-Id` 共同定义 user 隔离入口，session、quota、workspace 都按 user 归属管理。

02

User sandbox

隔离单位是 user，不是 session。同一用户的多个 session 共享长期 workspace、credentials 和运行历史。

03

Connector auth

Google Workspace、Notion、Feishu/Lark、Bilibili 的授权、状态、账号和断开流程都由后端控制面收口。

04

Jobs and schedules

`/v1/runs`、chat completions、approval bridge、run history、run-now 和后台 due schedule trigger 走同一条执行边界。

How it works

一次请求先进入控制面，再进入 Codex 执行面。

1

Request boundary

Server 校验 API key，解析 `X-Ripple-User-Id`，把请求绑定到当前 user 的隔离空间。

2

Control events

Chat 侧先处理 connector auth、schedule proposal、session 状态、workspace attachment 和权限桥接。

3

Codex run

Ripple 按 user 懒启动可信 app-server 进程，用 managed permissions profile 限制读写边界。

4

State returns

Codex event 被映射成 OpenAI-compatible response 或 SSE，同时持久化 session、job、usage 和输出。

Architecture

后端业务逻辑留在 Rust Server，客户端保持轻量。

crates/ripple-server

独立 Rust 控制面，注册 `/v1` API，处理鉴权、配额、状态和兼容响应。

codex/app_server.rs

Codex app-server JSON-RPC provider，按 user 懒启动可信服务端进程。

sandbox.rs

维护 `.ripple/sandboxes/<user_id>` 的 workspace、credentials、sessions 和 nsjail 配置。

sessions.rs + jobs.rs

保存 session metadata/messages、run history、events、outputs、usage 和 lifecycle 状态。

api/connectors.rs

收口 Notion、Google Workspace、Feishu/Lark、Bilibili 的 auth、status、accounts 和 disconnect。

api/schedules.rs

提供 schedule CRUD、run-now、历史查询和后台 due schedule trigger。

skills.rs

渲染 Markdown/YAML frontmatter skill manifest，交给 Codex 自行读取对应 `SKILL.md`。

app

Vite + React + Tauri 客户端，覆盖 Web、macOS、iOS、Android，只调用 Ripple `/v1` API。

Current State

Rust 主链路已成形，剩下的是真实运行边界的硬化。

已经迁移到 Rust

  • 配置加载、API key middleware、user id 校验和 quota。
  • sessions、workspace files、documents、users、runs、chat completions。
  • connector list/status/auth/disconnect/accounts。
  • Codex approval bridge、managed permissions profile、skill manifest。

正在重点 hardening

  • 真实 Codex streaming 事件和 attachment follow-up fixtures。
  • chat 侧 schedule creation 在真实 extraction 输出下的端到端链路。
  • 真实 nsjail runtime 下 connector CLI auth/status flow。
  • 确认旧客户端不再依赖后，清理 deprecated `/v1/tasks` compatibility。

Quickstart

本地启动一前一后两条进程。

先复制配置并准备服务端 Codex 登录态，再启动 Rust 后端。Web/Tauri 开发客户端位于 `app`，开发模式会把 `/v1` 代理到本地 `8810` 端口。 

cp config/settings.yaml.sample config/settings.yaml
CODEX_HOME=.ripple/codex-service-home codex login
cargo run -p ripple-server

cd app
bun install
bun run dev
