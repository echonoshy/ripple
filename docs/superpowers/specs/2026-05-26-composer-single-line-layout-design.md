# SessionComposer 统一单行布局设计方案

## 1. 背景与目标
在目前的 `SessionComposer.tsx` 中，在大屏和移动端/小屏下存在两套不同的 UI 布局。
- **大屏（PC）下**：使用“上方输入框、下方灰色工具栏（包含模型文字选择按钮、发送按钮）”的双行结构。
- **小屏下**：使用“一横行（包含最左侧的附件和 Sparkles 图标、中间输入框、最右侧发送按钮）”的单行结构。

这导致了冗余的 DOM 结构、两个不同的发送按钮状态、两套模型切换事件处理机制，给代码维护与设计风格的统一带来了困难。
本设计的目标是**在所有屏幕尺寸下完全统一为手机端的高极简单行布局**，消除 PC 端的双行冗余。

## 2. 方案设计

### 2.1 界面结构合并
我们将把所有的输入交互和控制元素合并到同一行：
`[ 附件按钮 ]` + `[ 闪烁(Sparkles)模型切换按钮 ]` + `[ 弹性文本输入框 ]` + `[ 发送/停止按钮 ]`

1. **左侧按钮组**：
   - 包含快捷斜杠命令检测挂载点 `quickActionsRef`。
   - `Paperclip` 附件按钮。
   - `Sparkles` 模型下拉菜单，在所有尺寸下点击都从左侧/上方弹出小型浮动菜单。
2. **中间文本框**：
   - 自由弹性伸缩，取消 `sm:w-full` 或 `sm:leading-6` 的繁多断点，保证其始终占据剩余的整行空间。
3. **右侧操作按钮**：
   - 统一由 `onSend`/`onStop` 驱动。
   - 去除原先 PC 端的 `sm:hidden` 和 `sm:inline-flex` 冗余按钮控制，使用统一的圆形渐变风格按钮。

### 2.2 事件及 Ref 简化
- 移除大屏底部的 `modelDropdownLargeRef`。
- 保留 `modelDropdownSmallRef` 并重命名为 `modelDropdownRef`。
- 将原本的双层点击外部关闭下拉框的逻辑统一合并。
- 移除被舍弃的 PC 底部灰色边框及模糊面板 `className="hidden items-center justify-between gap-2 pt-0.5 sm:flex ..."`。

## 3. 影响评估与测试
- **兼容性**：不改变现有的任何 `SessionComposerProps` 定义，对父组件 `SessionPage.tsx` 完全透明。
- **响应式表现**：在大屏下，单行输入框会横向拉长，左右两边是功能按钮，依然极其精致且美观，极大地提高了空间利用率。
- **测试**：需验证 `SessionComposer.test.tsx` 中的功能是否完好，并进行编译/打包校验。
