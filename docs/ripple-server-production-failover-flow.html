Ripple Server SSD + NAS 主备方案

大 workspace 不落本机盘：控制面和运行时留 SSD，用户 workspace 和大产物放共享 NAS，主备机器都挂载同一份 NAS。

V1 边界 SSD 跑控制面/runtime NAS 承载 workspace/artifacts NAS 备份交给厂商快照 脑裂和租约另行处理

方案判断

这个版本更适合大用户目录：NAS 解决容量和主备共享问题，SSD 保住 SQLite、Codex runtime、凭证和 cache 的稳定性。

推荐 V1 workspace 上 NAS runtime 留 SSD 减少主备同步

整体架构

主从机器共享同一台 NAS；新主接管后直接看到同一份用户 workspace。控制面 SQLite、Codex runtime、凭证和 cache 仍放各自本机 SSD。

切换流程

主机故障时只需要切网关和启动新主；workspace 已经在 NAS 上，不需要从旧主同步大文件。

Node A 正常服务

请求走网关到 Node A；Node A 写本机 SSD 上的控制面/runtime，同时读写 NAS 上的 workspace。

Node A 故障

运行中 job 中断；用户大文件仍在 NAS，未绑定旧主本机盘。

网关切到 Node B

Node B 使用自己的 SSD runtime，并挂载同一个 NAS workspace；无需同步大目录。

NAS 由厂商快照保护

误删、误改走 NAS 快照恢复；需要异地容灾时再把快照或备份包归档到 OSS/COS。
